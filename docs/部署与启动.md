# 部署与启动

> 适用版本：2026-10-08（P1 + P2 已收口）
> 所有组件都跑在本机，监听地址一律绑 `127.0.0.1`，不对局域网开放。

---

## 1. 拓扑与端口

| 组件 | 形态 | 地址 | 说明 |
|---|---|---|---|
| PostgreSQL 17.11 + pgvector 0.8.6 | Docker 容器 `assistant-pg` | `127.0.0.1:5432` | 库 / 用户均为 `assistant`，数据卷 `assistant_pg_data` |
| 后端 | 本机 JVM（可执行 jar） | `127.0.0.1:9090` | Spring Boot 3.5.16 |
| 前端 | Vite 开发服务器 | `127.0.0.1:5173` | 被占用时 Vite 会自动改用 5174 |

## 2. 启动顺序

### 2.0 一键启动（推荐）

双击根目录 **`启动.bat`**（等价于 `pwsh deploy\start-all.ps1`）：
自动切到 Java 17 → 起数据库容器（**仅当未运行时**，否则不重建）→ 缺 jar 或 jar 不可执行（上次构建被中断留下的瘦 jar）时 `mvn package` → 起后端 → 新窗口起前端 → 打开浏览器。

- 可选参数：`启动.bat -Rebuild`（强制重新打包后端）、`-SkipFrontend`、`-NoBrowser`。
- 前提：Docker Desktop 在跑、`deploy\.env` 已填、模型配置已在「系统配置」页填过一次。

> 一键脚本是分步命令的封装，下面 2.1~2.3 仍保留，排障时按它逐步执行。

### 2.1 先确认数据库容器在跑

```powershell
docker ps --format "{{.Names}}  {{.Status}}"
```

应看到 `assistant-pg` 是 `Up`。

**重建数据库容器**（当前**没有**脚本，下面是等价命令；只在数据卷丢失或换机器时才需要）：

```powershell
docker run -d --name assistant-pg --restart unless-stopped `
  -p 127.0.0.1:5432:5432 `
  -e POSTGRES_USER=assistant `
  -e POSTGRES_PASSWORD=<见 deploy\.env 的 PG_PASSWORD> `
  -e POSTGRES_DB=assistant `
  -v assistant_pg_data:/var/lib/postgresql/data `
  pgvector/pgvector:pg17
```

镜像就是 `pgvector/pgvector:pg17`，卷名就是 `assistant_pg_data`。**不需要手工建表**：后端启动时会幂等执行
`backend/src/main/resources/db/schema.sql`（建表 + 建索引 + 写种子数据）。

### 2.2 启动后端

```powershell
cd backend
mvn -o -B package                 # 改了 Java 代码才需要，离线可构建
cd ..
pwsh deploy\restart-backend.ps1   # 停旧进程 → 启动 → 等就绪 → 打印本地自检
```

> **必须在不受沙箱/防火墙限制的终端里启动。**
> 受限终端里 JVM 出网会被拒（Windows `WSAEACCES`，日志里是 `Permission denied: no further information`），
> 表现是所有公网模型接口"调用失败"。这不是配置错，是进程被拦了。

- 日志：`backend\logs\app.log`、`backend\logs\app.err.log`
- PID：`backend\logs\app.pid`（`restart-backend.ps1` 靠它停旧进程）
- 口令等敏感配置由 `deploy\start-backend.ps1` 从 `deploy\.env` 注入环境变量，不写进代码与命令行

### 2.3 启动前端

```powershell
cd frontend
npm run dev          # http://127.0.0.1:5173 ，/api 由 Vite 代理到 9090
```

生产产物（需要给静态服务器托管时）：

```powershell
cd frontend
npm run build        # 产物落 frontend\dist
```

## 3. 账号

账号存在数据库里，**初始**口令从 `deploy\.env` 读：`ASSISTANT_ADMIN_PASSWORD` / `ASSISTANT_DEMO_PASSWORD`。
口令只在账号不存在时用于初始化，已存在的账号不会被覆盖（改密走 `POST /api/auth/password`）。

| 账号 | 角色 | 能做什么 |
|---|---|---|
| `admin` | 管理员 | 全部文档（含"秘密"级）+ 运行记录页 + 配置页 + 同步/重解析 |
| `demo` | 只读 | 只能看到有权限的文档；看不到运行记录页，也没有配置入口 |

## 4. 验收脚本

```powershell
pwsh tools\run-acceptance.ps1              # 全套串行：13 个脚本，日志落 target\acceptance\
pwsh tools\run-acceptance.ps1 -SkipSlow    # 跳过 30 题跑分与界面实拍（省时间与 token）
```

也可以单独跑某一份：

```powershell
pwsh tools\verify-auth.ps1          # 登录、会话、角色、文档级 ACL 可见性
pwsh tools\verify-retrieval.ps1     # 检索、权限过滤、版本冲突、双阈值、检索账本
pwsh tools\verify-generation.ps1    # 问答、引用核对、四类拒答、token 账本（真实调用模型）
pwsh tools\verify-parse.ps1         # 自建解析、幂等、页码独立复核（pypdf，与后端 PDFBox 不同实现）
pwsh tools\verify-hybrid.ps1        # 关键词通道的权限、短问题撞长块、两路名次账本（真实调用模型）
pwsh tools\verify-observe.ps1       # 运行记录、耗时分解、token 与费用口径、账本权限
pwsh tools\verify-questions.ps1     # 30 题跑分与阈值校准（真实调用模型 30 次，1~3 分钟）
pwsh tools\verify-questions.ps1 -Set p3-30.json   # P3 触发证据题集（多跳/聚合/表格行 30 题，末尾按题型归类失败）
pwsh tools\verify-deep.ps1          # P3a 深度通道：AC-P3a-001~008（四道首批题 + 预算/取消/单跳/越权）
pwsh tools\verify-deep.ps1 -All     # 深度通道上跑完整个题集（每题 5~20 秒，比快速问答慢得多）
pwsh tools\verify-deep.ps1 -Ids P23,P27   # 只跑指定题
pwsh tools\verify-security.ps1      # 明文密钥、日志、slug 核查（会短暂改写一次 LLM Key 再还原）
pwsh tools\verify-document-view.ps1 # 文档查看三入口：403 一致、水印（PDFBox 提文本核对）、20MB 拒绝、只读性
node tools\verify-ask-page.mjs      # 问答页流式、引用跳原文、拒答渲染、两种宽度实拍（需 5173 + 模型）
node tools\verify-noperm-domain.mjs # "仅含无权限文档的知识域"（会临时改 ACL，跑完必还原）
node tools\verify-document-view-ui.mjs # 文档表「解析」列、查看器（原文/Markdown）、引用跳原文高亮实拍
```

`verify-document-view.ps1` 需要 **java 17 + 本地 `.m2` 里的 PDFBox/FontBox**（用 `tools/PdfText.java`
提取 PDF 文本核对水印——AC-D-008 明确不接受"看截图"判定）；缺依赖时脚本会直接报出缺哪一个。

**四条硬性注意事项：**

1. **必须串行执行。** 这些脚本会改状态（改密、注销会话、临时改 ACL、临时改密钥、强制重解析），并行时会互相注销
   令牌或互相覆盖状态，表现为一堆 401 的**假失败**。
2. **必须在能访问 Docker 管道的终端里跑。** `verify-auth` / `verify-parse` / `verify-hybrid` / `verify-observe` /
   `verify-security` / `verify-noperm-domain` 都要用 `docker exec psql` 直连容器核对库内事实。
3. **判定看 `[FAIL]` 计数与末尾汇总，不看退出码。** 脚本用 `$ErrorActionPreference = 'Continue'` 是为了跑完全部检查，
   不会在首个失败处中断。
4. **中断可能留下残留。** 脚本自带还原，但"还来得及还原"是有前提的：
   - `verify-noperm-domain.mjs`：`select count(*) from document_acl where subject_value = '__t12_no_permission__'`，非 0 说明没还原；
   - `verify-observe.ps1`：`app_setting` 里的单价字段应被清空；
   - `verify-security.ps1`：`llm.apiKey` 临时被改成金丝雀值再还原。**在沙箱里跑这一步会读不到原值、把金丝雀留在库里**
     （2026-10-08 真实踩过，用数据库容器环境里的 `GENERIC_OPEN_AI_API_KEY` 按指纹比对才取回），所以务必在不受限终端跑。

## 5. 常见故障对照

| 现象 | 真实原因 | 处理 |
|---|---|---|
| 问答报 503 `生成模型调用失败` | 不是"知识库没有"，是模型出口坏了（Key 错、出网被拦、配额） | 查 `backend\logs\app.log`；配置页点"测试"；确认终端不受限 |
| 同一问题偶发拒答 | 阈值本来就分不开两类样本（见需求文档 §10.11） | 别调阈值；根因在检索质量 |
| 卡在「启动后端…」很久，最后报后端没就绪 | 上次 `mvn package` 被中断，`target` 里留下的是没有 `Main-Class` 的瘦 jar：`java -jar` 立刻退出，探活白等 | 脚本现在会立刻报「不是可执行的 Spring Boot 包」并自动重建；手工重建：`cd backend; mvn -o -B package` |
| 报「前端需要 Node 18+」，或前端窗口里 vite 报 `Unexpected token '??='` | nvm 停在 Node 18 以下（本机 2026-10-13 停在 v14.15.4，而 vite 5 要 18+） | `nvm use 22.22.0` 后重新双击「启动.bat」；只想起后端加 `-SkipFrontend` |

## 6. 停服与重置

```powershell
# 停后端
Stop-Process -Id (Get-Content backend\logs\app.pid)

# 清空索引重来（索引全丢，需要重新 scan）
# 然后：POST /api/ingest/scan（幂等接口，会在同步时把缺失的补回去）
```

数据库重置是破坏性操作（`docker rm -f assistant-pg` 只删容器，数据在命名卷里；
要连数据一起删得删卷），本文档不提供命令——需要时手工确认目标卷后再执行。
