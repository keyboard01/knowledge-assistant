# 功能说明

> 面向使用者与评估者，说明本系统**能做什么、怎么用、边界在哪**。
> 部署方式见 [`交付部署.md`](交付部署.md)，架构与接口细节见 [`架构说明.md`](架构说明.md) / [`接口契约.md`](接口契约.md)。

---

## 1. 系统定位

企业知识助手把公司内部资料（制度、技术文档、维修手册等）建成**可检索、可引用、可追溯**的知识库，
用大模型**只依据检索到的证据作答**，并标注引用来源；证据不足时**明确拒答**，不编造。

一句话：**答案必须能指回原文，指不回去就不回答。**

---

## 2. 角色与权限

系统分**两个入口**：用户门户（问答 / 文档 / 上传）与管理控制台（`/admin.html`，域 / 文档 / 用户 / 授权 / 运行记录 / 系统配置 / 对外接入）。

| 角色 | 能做什么 |
|---|---|
| `admin`（管理员） | 全部文档（含"秘密"级）、系统配置、知识域与工作区授权、用户管理、文档上传/同步/审核、运行记录、对外密钥 |
| `hr` | 可见"秘密"级人事文档（保留角色） |
| `ops`（运营/业务） | 默认角色，仅可见被授权文档；可上传到被授权的域 |
| `viewer`（只读，如 demo 账号） | 只能问答与检索自己有权限的文档；看不到管理入口 |
| `service`（服务账号） | 供对外 API Key 绑定的非交互账号，无管理权限 |

- 登录用本地账号 + 服务端会话（令牌只存哈希，可即时撤销）；若已配置钉钉，还可用**钉钉内免登**。
- **权限两道门，依次下推**：先**工作区（域）级授权**，再**文档级 ACL**；没权限的片段根本不进入检索候选，也不会出现在引用与日志里。两级都是 fail-closed。
- **只有"现行"文档可被检索与查看**：草案与废止既不进证据、也打不开原文——用户上传的文档要管理员审核通过（转"现行"）后才进入知识库。

## 3. 功能清单

### 3.1 知识问答（核心）
- 选**知识域** → 输入问题 → 流式得到答案。
- 答案里每条结论带**引用编号**（如 `[1][3]`），点编号可定位到页面内对应片段。
- 每条引用可点「看原文」打开整份文档（PDF 预览 / Markdown 视图，带水印、走文档级权限复核）。
- 顶部显示本次的**证据数、引用条数、耗时、token**。
- **两种模式**：
  - 快速问答：一次检索 + 一次生成；
  - 深度分析：把问题拆成多条子问题 → 多轮取证据 → 分步作答，耗时更长但更完整，过程可见、可取消。

### 3.2 检索
- **混合召回**：向量召回（pgvector HNSW）+ 关键词召回（pg_trgm），用 RRF 融合（只看名次，避免把两种不可比的分数相加）。
- **引用可解释**：每个片段带页码、章节路径、两路各自名次。
- **版本并列与冲突提示**：同一文档编号出现多个版本时并列展示并标记冲突，不悄悄挑一个。
- **"没找到" vs "没权限"分开**：被权限挡下会明确提示"另有 N 条更相关的命中你无权访问"。

### 3.3 生成与拒答
- **双阈值闸门**：向量/关键词两路任一足够强才允许作答；都不够强就拒答，**不调用模型**（省 token，且拒答原因可统计）。
- **引用校验**：模型输出里的引用编号越界、或被 `max_tokens` 截断，一律按拒答处理，**不给半句话**。
- 拒答（知识库里没有）与 503（模型/向量化故障）**分开报**，不把系统故障说成"我们没有这个制度"。

### 3.4 文档接入
三种入口，走同一条链路（自建解析 + 按密级写 ACL）：

- **管理员上传**：在「文档与同步」点「上传文档」，填编号/标题/版本/密级等并选文件（PDF / DOCX / PPTX / XLSX / 图片）。
- **用户上传（待审核）**：普通用户在用户门户「文档中心」提交，落在**草案·未生效**（密级强制"内部公开"），
  管理员在控制台「待审核」里通过（转现行）或驳回（转已废止）。用户只能覆盖**自己上传且尚未生效**的文档，
  覆盖他人的现行/机密文档会被拒绝。
- **目录同步**：把文件放进 `knowledge/<知识域>/` 并在 `knowledge/manifest.json` 登记，点「立即同步」。

其它接入相关能力：
- **幂等**：内容没变就不重复上传、不重算向量（内容哈希判定）。
- **失败可重试**：每次尝试留痕，失败原因可读，可单个重试或全部重试。
- **解析预览**：把某份文档解析出的"块"列出来人工确认，与入库走同一条解析路径。
- **重建片段**：解析器/分块规则变化或开启增强后，一键重建自建片段。

### 3.5 知识域（知识库）管理
- 新建 / 改名 / 停用 / 删除知识域（删除要求该域下无文档）。
- 知识域是检索与授权的顶层分组。

### 3.6 文档版本
- 文档有**版本号**与**状态**（现行 / 已废止 / 草案）。
- 可一键切换状态；「传新版本」= 上传同一编号、新版本（生成新的一行，旧版保留）。

### 3.7 运行记录（账本）
- 每次问答一条记录：谁、哪个域、原问题、命中片段、耗时分解、token、**费用**。
- 费用按"提问当时的单价"快照，事后改价不影响历史账；未配单价记"未计费"而不是 0。
- 片段级明细含：两路名次、是否被引用、页码、分数。
- 仅管理员可见（账本里是所有人的提问原话）。

### 3.7.1 用户反馈（赞 / 踩 + 原因）
- 问答结果下方可直接👍/👎。**点踩必须选原因**（答非所问 / 引用不对 / 内容不全 / 已过期 / 其他），
  可附 500 字以内的补充说明；同一个问题问两次也不会评错——评价挂在**这一次**的账本行上（`traceId`）。
- 原因写成固定枚举而不是自由文本：自由文本聚不了类，也就指导不了优化。
- 权限：只能评价自己的问答（管理员可代评）。
- 管理端「运行记录」按原因聚合差评、显示满意率（分母只算评过价的条数），并可筛选查看。

> 为什么值得做：评测题集只有 60 道人工题，覆盖面靠人想；一次带标签的"踩"就是一条真实分布上的失败样本。

### 3.7.2 评测（离线跑分与趋势）
- 管理控制台「评测」：选题集（`tools/questions/*.json`）+ 模式 → 跑分。
  - **retrieval**：只跑检索，秒级、不花生成费用，适合每次改动后随手跑；
  - **full**：走完整问答（30 题几分钟，会真调模型）。
- 指标落库、可跨次对比：通过率、**hit@k**、MRR、引用正确率、拒答准确率、**泄露数**（必须为 0）、
  平均耗时与费用；失败用例可下钻到具体题号与失败原因。
- 命令行回归门 `tools\eval-gate.ps1`：跑一次并与同题集的上一次对比，**关键指标退步就以非零退出码结束**
  （泄露 > 0 是红线；通过率降 > 5 个百分点、hit@k 降 > 3 个百分点算退步）。

### 3.8 系统配置
分组配置，密钥只存服务端、接口只回显掩码（整页 **admin-only**）：

| 分组 | 作用 |
|---|---|
| 向量化 Embedding | 决定"能不能凭意思检索到"，入库后必须保持一致 |
| 生成模型出口 | 答案生成、查询改写、引用校验用 |
| 文档同步 | 文档根目录、片段上下文增强开关 |
| 重排 Rerank（可选） | cross-encoder 精排，默认关闭 |
| 版面分析（可选） | 接外部版面分析服务解析扫描件/双栏/跨页表格，默认关闭 |
| 图片理解 Vision（可选） | 「找图」用的视觉模型（生成图片描述与图内文字）；默认关闭，关闭时不抽不描述图片 |
| 图片视觉向量（可选） | 「找图」的跨模态召回（如 `qwen2.5-vl-embedding`）：把图片与查询文本编码进同一空间，补上"只靠描述"搜不到的纯视觉特征；默认关闭 |
| 评测 | 题集目录（默认 `tools/questions`）与默认模式（`retrieval` 秒级不花钱 / `full` 走全链路） |
| 钉钉（身份源，可选） | AppKey/AppSecret 等；留空即禁用，用于组织同步与内免登 |

每组都带「测试连接」探活。

### 3.9 用户与权限管理（admin）
- 「用户与角色」：建号、改角色/部门、启用/停用、重置密码。
- **租户归属（多项目接入 S2）**：建号/改号时可指定这个账号属于哪些租户（决定它能看见哪些知识域），
  留空落默认租户；列表会显示每个账号的租户。平台管理员跨租户可见，不受此限制。
- **租户管理员（S3）**：`adminTenantCodes` 把一个账号设为某租户的**管理员**——它能建/改/删该租户的域、
  改该租户的域授权、审核该租户的文档，但**看不到也管不了别的租户**。守卫：不能移除某个租户的最后一个管理员。
  租户管理员登录管理控制台后只看到「知识域管理 / 工作区授权 / 文档与同步」三个页签。
- 两条硬规则：不能停用或降级**最后一个管理员**；停用或重置密码会**立即**作废该账号的全部会话。
- 也可一键「从钉钉同步」，把组织通讯录落成账号（见 3.12）。

### 3.10 工作区授权（admin）
- 「工作区授权」：按知识域设置谁能看——主体支持**所有人 / 角色 / 部门 / 用户**。
- fail-closed：一条规则都没有的域只有管理员可见；新建域默认公开（对所有人可见）。
- 撤销某个域的公开授权后，该域对普通用户立即消失（但管理员始终可见，便于管理）。

### 3.11 对外接入（admin）
- **API Key**：为外部系统签发密钥，**绑定一个已有账号**，可见范围完全由该账号的角色/部门决定。
  明文只显示一次；可停用/吊销；停用绑定账号会连带使其失效。
- **MCP 端点**：`POST /api/mcp`（Streamable HTTP / JSON-RPC 2.0），用同一把 API Key 作 Bearer。
  暴露四个工具：`search_documents`（检索）、`list_domains`（可见域）、`read_document`（按 id 读原文）、
  `search_images`（找图）。
- 外部也可以直接用 HTTP 调现有只读接口（检索 / 问答 / 文档 / 域列表），带上 `X-API-Key` 即可。

### 3.12 钉钉接入（可选，留空即禁用）
- **组织同步**：从钉钉通讯录递归拉部门与人，落成本地账号（默认 `ops`，**永不给 admin**）。
- **内免登**：在钉钉客户端内打开系统时自动登录（无需扫码、无需输密码）。
- 未配置凭据时：登录页不显示钉钉入口，同步接口直接回"未配置"，不影响其它功能。

### 3.13 找图（图片素材）
- 用户门户「找图」：选知识域 + 输入描述 → 图墙（缩略图 + 描述 + 来源文档），可「看大图」、可「来源文档」。
- 图片来源：文档（PDF / DOCX / **PPTX**）里的**内嵌图**，以及**直接上传的图片**（同样走上传审核：草案 → 现行）。
- 只有**现行**文档的图片能被搜到；可见范围与文档完全一致（域级 + 文档级 ACL）。
- 描述与图内文字由**视觉模型**生成（「系统配置 → 图片理解」，默认关闭）；关闭时图片不抽取、不描述，
  也不影响文档正常入库。管理员可在「文档与同步」看图片资产状态并「重建图片索引」。
- 若另开「图片视觉向量」（多模态模型），检索会多一路**跨模态**召回，能命中纯视觉特征。
- 已知边界：只开「图片理解」时靠"文字描述 + 图内文字"检索，**纯视觉特征**搜不到（开视觉向量可缓解）。

## 4. 可选增强能力（默认全部关闭）

| 能力 | 开启后 | 代价 |
|---|---|---|
| 重排（P0） | RRF 之后用 cross-encoder 精排候选，压掉"语义相近但答非所问"的片段 | 多一次模型调用；只改排序、不改作答阈值口径 |
| 查询改写（P1） | 原问题生成 2~3 条变体并行召回，缓解"口语化提问对不上正式表述" | 多一次模型调用 |
| 上下文增强（P1） | 入库时给每个片段补一句上下文，随片段一起向量化 | 入库期一次性成本；开启后需重建片段 |
| 版面分析（P1） | 用外部服务解析复杂排版 | 依赖外部服务；不可用自动回落内置解析 |

> 这些开关都在「系统配置」里，关闭时行为与引入前一致（fail-open，失败退回原状）。

## 5. 使用流程（最短路径）

管理侧（打开 `http://127.0.0.1:5173/admin.html`）：

1. 管理员登录 → 「系统配置」填好向量化与生成模型出口，测试连接通过。
2. 「知识域管理」新建知识域。
3. 「工作区授权」设置谁能看这个域（新建域默认公开）。
4. 「文档与同步」上传文档（或放目录后「立即同步」）；有用户提交的草案时在「待审核」处理。
5. 「用户与角色」按需建号，或点「从钉钉同步」。

用户侧（打开 `http://127.0.0.1:5173`）：

6. 登录 → 「知识问答」选域提问，看答案与引用；「文档中心」可查看可见文档、提交上传（进待审核）。

复盘 / 集成：管理员在「运行记录」看每次问答的命中与成本；在「对外接入」签发 API Key、查看 MCP 端点。

## 6. 已知边界

- 单机、单租户，全部监听 `127.0.0.1`；不做多租户与分布式向量库。
- 存储为 PostgreSQL + pgvector 单库；向量维度在 DDL 固定，换向量化模型需全量迁移。
- 文档**没有删除接口**，下线只能改状态（现行/废止）。
- **文件类型**：文本文档支持 PDF / DOCX / **PPTX** / **XLSX**；图片（png/jpg/jpeg/gif/bmp）可**直接上传**或从 PDF/DOCX/PPTX 中抽取。
  旧 **`.ppt` / `.xls` 不支持**（前者依赖离线无 jar 的 `poi-scratchpad`，后者与 xlsx 的解析分支不同暂不合并）；扫描件（无文字层的 PDF）仍**无 OCR**；PPT 生成未实现。
  **XLSX 只取单元格文本**（每张工作表一个标题、行按表头拼前缀，行数有护栏），表里的图片与图表不抽取。
- **找图默认靠文字**：图片检索用的是视觉模型生成的描述与图内文字（文本 embedding）——**纯视觉特征默认搜不到**；
  开「图片视觉向量」后才会多一路跨模态召回。未配置视觉模型时整条图片链路跳过。
- 复杂排版（双栏、扫描件）依赖可选的版面分析服务；内置解析为启发式。
- **工作区授权只有"读"**：可见即可上传；用户上传靠"默认草案 + 审核 + 覆盖守卫"兜底，没有独立的写权限。
- **对外 API Key 没有 scopes**：权限完全等于绑定账号的角色/部门——**绑 `admin` 的 Key 等于把管理员权限包出去**（能上传、改文档状态、改系统配置）；也没有有效期与 IP 白名单。要"只读的钥匙"目前只能造一个受限账号再绑。多项目共用时的方案见 [`多项目接入方案.md`](多项目接入方案.md)。
- **MCP 只提供 Streamable HTTP**（`POST /api/mcp`）：规范里的 `GET`（服务端推 SSE）与 `DELETE`（结束会话）也没实现，且**没有 stdio 传输**。影响只在客户端：Claude Desktop 这类默认只会启动本地进程的客户端要自备 stdio↔HTTP 桥（如 `mcp-remote`）；能配远程 MCP 的客户端填地址 + Key 即可。服务端不打算做 stdio——它是多用户 + ACL 的系统，stdio 的"进程即身份"跟它的鉴权模型不匹配。
- **钉钉未做真实联调**：本机无凭据、需出网，只验证到"留空即禁用 + 纯逻辑单测"；配好 AppKey/AppSecret 后需自行连通验证。
- 钉钉出站（发工作通知/群消息）尚未实现。
