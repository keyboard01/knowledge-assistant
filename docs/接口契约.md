# 接口契约

> 适用版本：2026-10-13（身份/权限地基 + 对外接入）
> 契约以代码为准（`backend/src/main/java/io/github/keyboard01/assistant/**/*Controller.java`），本文是摘要，
> 字段名与类型都取自代码里的 record 定义。

---

## 1. 通用约定

| 约定 | 内容 |
|---|---|
| 基址 | 后端 `http://127.0.0.1:9090`；前端开发时经 Vite 代理 `/api` → 9090 |
| 鉴权（浏览器） | `Authorization: Bearer <会话令牌>`；令牌是**不透明**值，服务端只存 SHA-256 |
| 鉴权（外部系统） | `X-API-Key: <密钥>`，或同样用 `Authorization: Bearer <密钥>`（MCP 客户端习惯）。密钥绑定一个账号，权限即该账号的角色/部门 |
| 免登录路径 | 只有 `POST /api/auth/login` 与整段 `/api/auth/dingtalk/**`（钉钉登录是"还没登录的人"在调）；其余 `/api/**` 默认拒绝 |
| API Key 不适用路径 | `/api/auth/**` **不接受** API Key（否则改密码会把凭据当作当前 token，误删该账号全部会话） |
| 身份来源 | **只能**由服务端推出（`CurrentUser`）：会话令牌或 API Key 解析出的账号。请求体里没有用户、角色、可见范围字段——传了也不生效 |
| 错误体 | 统一 `{"error": "<中文说明>"}`（MCP 端点例外，见 §11，回 JSON-RPC 错误对象） |
| 状态码 | `400` 参数不合法 · `401` 未登录/凭据错 · `403` 角色不足 · `404` 资源不存在 · `503` 模型或向量化服务不可用 |
| 403 vs 401 | 会话有效但角色不够是 403；会话无效是 401。前端据此决定"踢回登录页"还是"提示无权限" |
| 503 的语义 | **系统坏了**，不是"知识库里没有"。后者永远走 200 + 拒答（`refused=true`） |
| 角色 | `admin` / `hr` / `ops` / `viewer` / `service`（服务账号，供 API Key 绑定，无管理权限） |
| 端分离 | 用户门户 `/`；管理控制台 `/admin.html`（同一后端、同一登录令牌，仅前端入口与导航不同） |

## 2. 登录与账号（`/api/auth`）

| 方法 | 路径 | 权限 | 请求 | 响应 |
|---|---|---|---|---|
| POST | `/api/auth/login` | 匿名 | `{username, password}` | `{token, expiresAt, user: UserView}`；凭据错 401 |
| POST | `/api/auth/logout` | 登录 | — | `{ok: true}` |
| GET | `/api/auth/me` | 登录 | — | `{user: UserView}`；未登录 401 |
| POST | `/api/auth/password` | 登录 | `{oldPassword, newPassword}` | `{ok: true}`；旧密码错 **400**（不是 401，否则前端会把人踢回登录页） |
| GET | `/api/auth/users` | admin | — | `{users: [UserView]}`（与 `/api/admin/users` 同源） |

```text
UserView { id, username, displayName, roleCode, deptCode, enabled }
```

`GET /api/auth/dingtalk/**` 与 `POST /api/auth/dingtalk/callback` 均为**免登录**：

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/auth/dingtalk/enabled` | 匿名 | `{enabled}`：钉钉是否可用（开关打开且凭据齐全）。前端据此决定是否显示入口 |
| GET | `/api/auth/dingtalk/config` | 匿名 | `{enabled, corpId, agentId}`：钉钉 JSAPI（`dd.config`）所需的公开参数，**不含 appSecret** |
| POST | `/api/auth/dingtalk/callback` | 匿名 | `{authCode}` → `{token, expiresAt, user}`（钉钉内免登：authCode → userid → upsert 本地账号 → 签发会话）；未启用/凭据错 **400** |

账号管理（用户与角色）在 `/api/admin/**` 下，见 §10。

## 3. 知识域与自检（`/api/domains`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/domains` | 登录 | `{domains: [DomainView]}`；**只返回当前身份可见的域**（先过域级授权），`visibleDocuments` 是**当前身份可见**的文档数 |
| POST | `/api/domains` | **admin** | `{code, name, description?, enabled?} → `DomainView`；新建域默认公开（写一行 `ALL:*`）；code 限 `[a-z][a-z0-9_-]{1,31}` |
| PUT | `/api/domains/{code}` | **admin** | `{name?, description?, enabled?}` → `DomainView`；改 code / workspace_slug 不支持 |
| DELETE | `/api/domains/{code}` | **admin** | 204；**有文档则 400**（先清理或改为停用）；域级授权随外键级联删除 |
| GET | `/api/domains/selfcheck` | **admin** | 本地自检；`{ok, items: [{key, title, status, detail}]}`；启动时也会自动跑一次 |

```text
DomainView { code, name, workspaceSlug, description, enabled, visibleDocuments }
```

字段是白名单钉死的：**没有"文档总数 / 隐藏数"字段**，避免通过接口反推隐藏了多少文档。

### 3.1 工作区（域）级授权（`/api/admin/domains/{code}/acl`，admin）

两级门的第一级：**先过域级授权，再按文档级 ACL 判细粒度可见**。域级也是 fail-closed——一条规则都没有 = 只有管理员可见。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/domains/{code}/acl` | `{rules: [AclRuleView]}` |
| PUT | `/api/admin/domains/{code}/acl` | `{rules: [AclRuleView]}` → 整份替换（提交什么就是什么；空数组 = 只有管理员可见） |

```text
AclRuleView { subjectType, subjectValue, permission }   // subjectType ∈ ALL / ROLE / DEPT / USER；permission 恒 READ
```

- 新用户默认能看到的就是"公开域"（域里带 `ALL:*` 规则）。
- 检索、查看原文、上传统一调用 `DomainService.requireAccessible`，请求未授权域一律拒绝。

## 4. 文档与同步（`/api/documents`、`/api/ingest/**`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/documents` | 登录 | `{documents: [DocumentView]}`，**只返回当前身份可见的**。先过域级 + 文档级 ACL；再按状态收窄：**admin 看全部**（含待审草案，否则无法审核），**非 admin 只看「现行 + 自己上传的草案」** |
| POST | `/api/ingest/scan` | admin | 扫目录并按 manifest 登记表同步；`ScanSummary` |
| POST | `/api/ingest/reindex?force=` | admin | 重建自建 chunk；`force=true` 连内容没变的也重算；`ReindexSummary` |
| GET | `/api/ingest/tasks?limit=` | admin | `{tasks: [...]}`，limit 被夹到 1..500 |
| POST | `/api/ingest/tasks/{id}/retry` | admin | `FileResult` |
| POST | `/api/ingest/retry-failed` | admin | `{ok, results: [FileResult]}` |
| POST | `/api/ingest/parse-preview` | admin | `{documentId}` → `ParsePreview`：块级解析预览，与入库**同一条解析路径**（版面分析可用则用，否则内置），供人工确认解析质量 |
| POST | `/api/ingest/upload` | 登录 + 域可访问 | `multipart/form-data`：`file`(pdf / docx / pptx / **xlsx** / 图片 png·jpg·jpeg·gif·bmp) + `domainCode/docNo/title/version` + 可选 `docStatus/secrecy/ownerDept/effectiveFrom/effectiveTo` → `FileResult`。写盘 + 登记 `manifest.json` + 解析 + 按密级写 ACL；同一「编号+版本」重复上传视为覆盖。**非 admin 一律落「草案·未生效 + 内部公开」等审核**（提交里的状态/密级字段被服务端忽略）；非 admin 只能覆盖「自己上传且尚未生效」的文档，越权覆盖返回 **400**。**图片**（kind=image）不产 chunk，只建图片索引。单文件上限 50MB |
| PUT | `/api/documents/{id}/status` | admin | `{docStatus}`（现行 / 已废止 / 草案·未生效）→ `DocumentView`；只改状态，不重传、不重解析。**用户上传的审核动作（通过=转现行 / 驳回=转已废止）也走这里** |
| GET | `/api/documents/{id}/content` | 登录 + 文档 ACL + **可见状态** | Markdown 视图（JSON，`ContentView`）。可见状态口径与文档列表**完全一致**：admin 看全部，其余看「现行 + 自己上传的草案」——列表里看得到却点不开，是曾经真实存在过的缺陷 |
| GET | `/api/documents/{id}/file` | 登录 + 文档 ACL + 可见状态 | 原文预览：**内联** PDF（DOCX/XLSX 服务端重排成 PDF；PPTX 的内嵌图按幻灯片插回），字节带水印 |
| GET | `/api/documents/{id}/download` | 登录 + 文档 ACL + 可见状态 | 下载：**统一给 PDF**（同一份带水印字节），`Content-Disposition: attachment` |

```text
DocumentView { id, domainCode, docNo, title, version, docStatus, secrecy, ownerDept,
               mimeType, fileSize, indexStatus, chunkStatus, chunkCount, kernelDocName, lastError, uploadedBy,
               kind, assetStatus, assetCount }
ContentView  { documentId, domainCode, docNo, title, version, docStatus, secrecy, ownerDept,
               mimeType, originalPdf, watermarkText, markdown, blocks: [Block],
               pageOfChunk: {chunkId → 起始页}, chunkCount }
Block        { chunkId, kind, level, text, pageFrom, pageTo, sectionPath, sectionHead }
ScanSummary  { sourceRoot, startedAt, scanned, uploaded, skipped, failed,
               vectorCountBefore, vectorCountAfter, files: [FileResult] }
FileResult   { sourcePath, action, status, detail, domainCode, documentId }
ReindexSummary { total, indexed, skipped, failed, results: [...] }
```

`kind` = `text`（PDF/DOCX/PPTX，产 chunk）| `image`（直接上传的图片，不产 chunk）。
`assetStatus` = `NONE`/`INDEXED`/`SKIPPED`/`FAILED`，`assetCount` 是图片资产张数（见 §12）。
`uploadedBy` 是上传者用户名（目录扫描入库的为空），用于审核与「我的上传」。
`docStatus` 只有 `现行` 的文档参与检索与查看——**草案 / 已废止不进证据、也打不开原文**。
图片文档（`kind=image`）走 `/api/documents/{id}/file|content|download` 会返回 **400**（请在「找图」里看）。

`DocumentView` 刻意**不含** `sourcePath`（服务器内网路径）、`contentHash`、内部 id——这些是内部信息，
viewer 没必要看到。`vectorCountBefore/After` 是"上传成功 ≠ 入库成功"那条判据的对外证据。

### 4.1 查看三入口的共同口径（§13）

| 口径 | 说明 |
|---|---|
| 权限 | 每次请求**重新判**文档级 ACL（与列表、检索共用 `AccessFilter`）。**不存在与无权限同码**：一律 `403 {"error":"没有权限查看该文档"}`，响应体不含标题、编号、路径——否则仅凭状态码就能枚举库里有编号哪些文档 |
| 未登录 | `401`（走统一的登录拦截） |
| 水印 | PDF 由服务端**烧进字节**（45° 半透明重复，`账号 yyyy-MM-dd`，日期取服务端当天）。Markdown 视图无字节可烧，只在页面叠加 |
| 体积 | 源文件 > 20MB → `413 {"error":"文档体积 NNMB 超过在线查看上限 20MB，…"}`。水印要整份重写字节，没有 HTTP Range 分页这条路 |
| 审计 | 每次请求落一行 `document_view_log`（channel = `FILE`/`CONTENT`/`DOWNLOAD`，outcome = `OK`/`DENIED`，含水印串与来源 IP）。**拒绝也记**：那是最该被看见的事件。写审计失败只记 error 日志，不影响本次查看 |
| 只读 | 查看不改任何库内值：`content_hash`、`index_status`、`chunk_count`、`document_chunk` 行数在查看前后不变 |
| 缓存 | `Cache-Control: no-store`；DOCX 重排结果只缓存**未盖章**的字节（带某账号水印的成品绝不跨人缓存） |

## 5. 检索（`/api/retrieval/search`）

| 方法 | 路径 | 权限 | 请求 |
|---|---|---|---|
| POST | `/api/retrieval/search` | 登录 | `{domainCode, question, topN?, minScore?}` |

```text
RetrievalResult { evidences: [Evidence], insufficient, hint, accessNotice, diagnostics }
Evidence   { rank, documentId, docNo, title, version, docStatus, secrecy, ownerDept,
             kernelDocName, bestScore, fragments: [Fragment] }
Fragment   { chunkId, chunkIndex, text, score, distance, wordCount, pageFrom, pageTo, sectionPath,
             kind, keywordScore, vectorRank, keywordRank }
RetrievalDiagnostics { accessFilter, requestedTopN, minScore, answerMinScore, keywordMinScore,
                       kernelTopN, kernelHits, vectorHits, keywordHits, bestKeywordScore,
                       droppedUnauthorized, droppedUnknown, droppedNotIndexed, droppedDuplicate,
                       elapsedMs, rerankApplied, bestRerankScore, ... }
```

**重排（P0）**：`rerankApplied` 表示本次是否真的走了 cross-encoder 重排（未配置/失败时 `false`），
`bestRerankScore` 是本次最强重排分。重排**只改排序、不改口径**：`bestScore` 仍是**全局最强的向量余弦**
（不随重排换第一名而变），作答阈值 `answerMinScore` / `keywordMinScore` 也一字不动。重排失败一律 fail-open
（退回 RRF 原序），不影响检索是否出结果。

两个提示字段的读者不同，**不要合并**：

- `hint` 面向排障：为什么答不上来，含"没凑满 topN"这类接口层面的信息；
- `accessNotice` 面向用户：你看到的答案缺了证据（"另有 N 条更相关的命中你无权访问"）。

`diagnostics.droppedUnknown / droppedNotIndexed` 非 0 说明**文档还没就绪或已被删除**，
这是运维信号，不是用户信号。

## 6. 问答（`/api/generation`）

| 方法 | 路径 | 权限 | 请求 |
|---|---|---|---|
| POST | `/api/generation/answer` | 登录 | `{domainCode, question, topN?}` |
| POST | `/api/generation/answer/stream` | 登录 | 同上；响应是 `text/event-stream` |

```text
GeneratedAnswer { answer, citations: [Citation], refused, refusalReason, notice,
                  evidences: [Evidence], diagnostics, traceId }
Citation { rank, documentId, docNo, title, version, chunkId, pageFrom, pageTo }
```

`traceId` 是这次问答在账本（`qa_trace`）里的行号，**由服务端在答案算完之后回填**（要先有答案才能记账）。
前端靠它把"赞/踩"挂回**具体这一次**问答——只给问题原文的话，同一个问题问两次就分不清在评价哪一次。
账本写失败时它是 `null`，此时前端不显示反馈入口（宁可不评，也不留一条找不到归属的评价）。

**SSE 事件序列**（`evidences` → `delta`* → `verdict`，出错则 `error`）：

| 事件 | 载荷 | 说明 |
|---|---|---|
| `evidences` | `{evidences: [Evidence], insufficient}` | 先给证据，让界面能立即展示"检索到了什么" |
| `delta` | `{text}` | 正文增量；此时**结论未定** |
| `verdict` | `GeneratedAnswer` | 校验后的最终结论（引用越界/截断在这里才定为拒答） |
| `error` | `{error}` | 一旦推过第一个事件，HTTP 状态码已经是 200，失败**只能**靠这个事件表达 |

`refused=true` 时 `refusalReason` 是原因码（可统计），`evidences` 照样返回——用户需要知道检索到了什么，
才能判断是问题问偏了，还是库里确实没有。

## 7. 运行记录（`/api/observe/**`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/observe/traces?limit=&domainCode=&refused=` | admin | `{traces: [TraceRow], summary}`；`refused` 三态：不传=全部 / true=只看拒答 / false=只看放行 |
| GET | `/api/observe/traces/{id}` | admin | `TraceDetail`；不存在 404 |
| GET | `/api/observe/summary?domainCode=&refused=` | admin | `Summary` |
| GET | `/api/observe/price` | admin | `PriceSnapshot`，供界面说明"费用按什么价算" |
| **POST** | **`/api/observe/traces/{id}/feedback`** | **登录（限提问人本人 / admin 代评）** | 提交赞踩：`{rating: 1\|-1, reason?, comment?}` → `{traceId, rating, reason, commented}`。**点踩必须选原因**（白名单：答非所问 / 引用不对 / 内容不全 / 已过期 / 其他），点点赞时原因一律丢弃；重复提交按最新覆盖。原因非法 / 缺原因返回 **400**；不是自己的问答返回 **403** |
| GET | `/api/observe/feedback/reasons` | 登录 | `{reasons: [...], maxComment}`，前端 chips 与后端白名单同源 |
| GET | `/api/observe/feedback/summary` | admin | `{rated, likes, dislikes, likeRate, reasons: {原因 → 条数}}`；**满意率的分母只算评过价的条数** |

> 反馈是整个 observe 分区里**唯一不要求 admin** 的写入口：评价必须由提问人自己给出才有统计价值，
> 权限靠"这条账本是不是你提的问"来判（管理员可代评）。

```text
TraceRow   { id, createdAt, userName, domainCode, question, refused, refusalRule, insufficient,
             evidenceCount, citedCount, bestScore, modelCalled, promptTokens, completionTokens,
             totalElapsedMs, costTotal, priced, rating, feedbackReason }
TraceDetail(TraceRow, accessFilter, requestedTopN, minScore, answerMinScore, kernelTopN, kernelHits,
            droppedUnauthorized, droppedUnknown, droppedNotIndexed, droppedDuplicate, documentCount,
            versionConflict, retrievalElapsedMs, generationElapsedMs, model, outOfRangeCitations,
            truncated, promptPricePer1k, completionPricePer1k, evidences: [EvidenceRow])
EvidenceRow { rank, documentId, docNo, title, version, chunkId, chunkIndex, score, cited,
             pageFrom, pageTo, vectorRank, keywordRank, keywordScore }
Summary    { total, refused, insufficient, refuseRate, modelCalls, promptTokens, completionTokens,
             costTotal, pricedCount, unpricedCount, avgElapsedMs, maxElapsedMs, avgBestScore }
PriceSnapshot { promptPer1k, completionPer1k, note }
FeedbackSummary { rated, likes, dislikes, likeRate, reasons }
```

`rating` = 1 赞 / -1 踩 / `null` 未评价（`null` 与 0 是两件事，所以列上不设默认值）。

## 7.1 评测（`/api/eval/**`，整个控制器 **admin**）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/eval/runs` | `{set, mode}` → `RunDetail`。**同步执行**：`mode=retrieval` 只跑检索（秒级、不花生成费），`mode=full` 走完整问答（30 题约几分钟，真调模型）。`set` 是题集目录下的文件名（白名单，防路径穿越） |
| GET | `/api/eval/runs?limit=&set=` | `{runs: [RunRow], sets: [...]}`，按时间倒序，供趋势对比 |
| GET | `/api/eval/runs/{id}` | `RunDetail`（run + 逐题用例）；不存在 404 |

```text
RunRow    { id, createdAt, createdBy, questionSet, mode, status, total, passed, failed,
            hitAtK, mrr, citationAccuracy, refusalAccuracy, leakCount, avgBestScore, avgElapsedMs,
            promptTokens, completionTokens, costTotal, note }
CaseResult{ caseId, domainCode, asker, question, reasoning, expectedOutcome, actualOutcome, ok,
            failureReason, leaked, citationOk, traceId, hit, docRank, bestScore,
            expectedDocNos, citedDocNos, elapsedMs }
```

- `status` = RUNNING / DONE / FAILED：**先落 RUNNING、逐题回填**，跑到一半被打断也能看到已完成的部分。
- `hitAtK` / `mrr` 的分母只算**有期望文档的题**；`citationAccuracy` 只算 full 模式里真的作答的题。
- `leakCount > 0` = 权限回归（被挡文档出现在证据或引用里），是回归门的红线，不看 Δ。
- 每道题按题集里的 `asker` 取真实身份构造 `AccessSubject`，**不碰调用者的身份**，权限题走的就是线上那条路径。

`cited` 是"模型有没有引用它"，不是"有没有权限"——权限在检索阶段就判完了。
`costTotal` 为 `null` 表示**未计费**（没配单价），不是 0 元。
`chunkIndex` 是片段在文档内的序号（`document_chunk` 的唯一约束 `(document_id, chunk_index)` 的另一半）。
`chunkId` 是代理键（bigserial），强制重解析在历史上会换掉它；`(documentId, chunkIndex)` 不会漂移，
"点回原文"要用这一对。`null` 表示没有本地序号（无本地序号的片段，或历史悬空行）。

## 8. 配置（`/api/settings`，整个控制器 **admin**）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/settings` | **admin** | `{groups: [GroupView]}` |
| PUT | `/api/settings/{code}` | **admin** | `{values: {字段: 值}}` → `GroupView`；**只有这里允许携带明文密钥** |
| POST | `/api/settings/{code}/test` | **admin** | `TestResult {ok, message, detail}`，真实探活 |
| DELETE | `/api/settings/{code}/{field}` | **admin** | 清空单个字段 → `GroupView` |

`code` ∈ `embedding` / `llm` / `ingest` / `rerank`（P0 重排）/ `layout`（P1 版面分析）/ `dingtalk`（身份源）/ `vision`（图片描述）/ `image_embedding`（图片视觉向量）。
`ingest` 分组含 `sourceRoot`、`assetRoot`（图片资产目录，默认 `knowledge-assets`，不得位于 `sourceRoot` 之内）与 `contextual`（片段上下文增强）。
`rerank` / `layout` / `dingtalk` / `vision` / `image_embedding` 均为可选能力，默认关闭。

| 分组 | 字段 | 说明 |
|---|---|---|
| `dingtalk` | `enabled`(默认 false) / `appKey`(**非** secret，便于清空) / `appSecret`(secret) / `corpId` / `agentId` / `rootDeptId`(默认 1) / `defaultRole`(默认 ops，永不为 admin) | 组织同步与内免登 |
| `vision` | `enabled`(默认 false) / `baseUrl` / `apiKey`(secret) / `model` | 图片描述（VLM，OpenAI 兼容 content 数组） |
| `image_embedding` | `enabled`(默认 false) / `baseUrl`(默认百炼多模态端点) / `apiKey`(secret) / `model`(默认 `qwen2.5-vl-embedding`) | 跨模态图片向量（见 §12） |

> 配置接口整体 **admin-only**：密钥字段读取时虽已掩码，但能写就等于能改模型出口/密钥，属管理面。
> 非 admin 写配置返回 403（早期版本这里没有任何角色门，是一次已修复的安全缺陷）。

```text
GroupView { code, title, description, fields: [FieldView] }
FieldView { key, label, secret, hasValue, mask, value, hint, defaultValue }
```

**密钥字段三条硬规则**（AC-P1-012 / AC-P1-013）：

1. `secret=true` 的字段，`GET /api/settings` 里 `value` **恒为空串**，只回 `hasValue` 与掩码（形如 `sk-****1234`）；
2. 掩码与明文不可互推；
3. 保存配置的 PUT 体里可以带明文，但**不写日志**、响应体也不回显明文。

`llm.apiKey` 留空时回落到 `embedding.apiKey`（同一套账号时的便利，界面会显示"复用向量化分组的 Key"）。
注意：本项目当前 `llm.baseUrl` 与 `embedding.baseUrl` **不是同一个服务商**，所以这条回落只是在"两边同源"时才有意义。

## 9. 深度分析（`/api/deep`，P3a）

| 方法 | 路径 | 权限 | 请求 |
|---|---|---|---|
| POST | `/api/deep/answer` | 登录 | `{domainCode, question, runId?, maxSubQuestions?, maxToolCalls?, maxRounds?, maxElapsedMs?, maxCompletionTokens?}` |
| POST | `/api/deep/answer/stream` | 登录 | 同上；响应是 `text/event-stream` |
| POST | `/api/deep/cancel` | 登录 | `{runId}` |

```text
DeepAnswer { runId, domainCode, question, mode="deep", answer,
             sections: [Section], plan: [SubQuestion], steps: [Step], citations: [Citation],
             refused, refusalRule, notice, clarifyQuestion, stopReason, stopMessage,
             evidences: [Evidence], diagnostics: DeepDiagnostics }
Section     { index, question, text, citedRanks: [int], answered, refusalRule }
SubQuestion { id, question, why }
Step        { seq, action, detail, query, documentId, fromChunkIndex, newFragments, elapsedMs }
DeepDiagnostics { model, modelCalled, subQuestionCount, sectionCount, answeredSections, evidenceCount,
                  citedCount, toolCalls, rounds, promptTokens, completionTokens, elapsedMs,
                  budgetStop, stopReason }
```

**预算字段只能往小里填**：子问题 ≤4、工具调用 ≤10、轮数 ≤3、耗时 ≤120000ms、输出 token ≤12000；
超上限按上限算，不报错（`DeepBudget.of` 一侧夹死，前端拦不拦都不影响）。

**SSE 事件序列**（`plan` → `step`* → `evidences` → `delta`*/`section`* → `verdict`，出错则 `error`）：

| 事件 | 载荷 | 说明 |
|---|---|---|
| `plan` | `{runId, plan: [SubQuestion], budget}` | 拆成了哪几条子问题；此时还没开始检索 |
| `step` | `{step}` | 每一步查了什么、新带回几段——前端画"探索过程"靠它 |
| `evidences` | `{evidences: [Evidence], insufficient}` | 合并去重后的证据（全局连续编号） |
| `delta` | `{text}` | 分段正文的增量；与快速问答一样，此时结论未定 |
| `section` | `{section}` | 某一段子问题答完了（带 `citedRanks`），界面可以定稿这一段 |
| `verdict` | `DeepAnswer` | 最终结论 |
| `error` | `{error}` | 推过第一个事件后 HTTP 已是 200，失败只能靠这个事件表达 |

**`stopReason` 是合法状态而不是错误**，取值与含义：

| 取值 | 含义 |
|---|---|
| `DONE` / `MODEL_FINISH` | 证据齐了 / 模型说够了 |
| `NO_NEW_EVIDENCE` | 这一轮没有带回新片段——证据已到边界（不是"没查到"） |
| `REPEATED_QUERY` / `REPEATED_READ` | 模型重复了已经试过的查询 / 已经读过的那一段 |
| `PLANNER_UNUSABLE` | 模型没给出可识别的下一步动作，按现有证据作答 |
| `TOOL_CALL_BUDGET` / `ROUND_BUDGET` / `ELAPSED_BUDGET` / `TOKEN_BUDGET` | 触到预算上限（`diagnostics.budgetStop` 里是给人看的说明） |
| `CANCELLED` | 用户调了 `/api/deep/cancel`：返回"已取消"与已完成的部分，HTTP 仍是 200 |
| `CLARIFY` | 一条证据都没有，而拆解判定问题缺关键限定：`clarifyQuestion` 是要反问用户的那句话 |

`refused=true` 表示**知识库里没有**（`refusalRule` 给原因码）；模型/向量化不可用仍然是 `503`，与拒答分开。
澄清是"先查后问"：只有查过一轮仍没有任何证据、且拆解阶段判了 `needClarification`，才会走到 `CLARIFY`。

`POST /api/deep/cancel` 返回 `{cancelled: bool, note}`。取消别人的 `runId` 与"这个 `runId` 不存在"
返回同一句话（"该运行已结束或不存在"）——否则它就成了一个探测"别人在问什么"的工具。

## 10. 管理面（`/api/admin/**`，整个分区 admin）

`/api/admin/**` 由拦截器默认要求登录，各控制器再叠 `@RequireRole("admin")`。这是"管理端/用户端"分离的后端落点。

### 10.1 用户与角色

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/users` | `{users: [UserView]}` |
| GET | `/api/admin/roles` | `{roles: [{code, name, description}]}`（角色字典来自 `app_role`，前端下拉据此生成） |
| POST | `/api/admin/users` | `{username, displayName?, roleCode, deptCode?, password}` → `UserView`；用户名重复 **400**；未知角色 **400** |
| PUT | `/api/admin/users/{id}` | `{displayName?, roleCode?, deptCode?, enabled?}` → `UserView`；**不能停用/降级最后一个管理员**（400） |
| POST | `/api/admin/users/{id}/password` | `{newPassword}` → `{ok:true}`；长度 < 8 → 400 |

停用账号或重置密码会**立即作废该账号的全部会话**（不等令牌过期）。

### 10.2 对外 API Key

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/api-keys` | `{keys: [ApiKeyView]}`；**只含前缀**，不含明文 |
| POST | `/api/admin/api-keys` | `{name, userId}` → `{key, client}`；`key` 是明文，**只此一次**；`defaultRole=admin` 的账号不禁止绑定，但建议用 `service` 角色 |
| POST | `/api/admin/api-keys/{id}/enabled` | `{enabled}` → `ApiKeyView` |
| DELETE | `/api/admin/api-keys/{id}` | 204；吊销后立即失效 |

```text
ApiKeyView { id, name, keyPrefix, userId, username, displayName, enabled, createdBy, createdAt, lastUsedAt }
```

密钥与登录令牌同规格（256 位随机 + SHA-256）：库里只存哈希，明文只在创建响应里出现一次。
**权限完全由绑定账号决定**（角色/部门 → `AccessFilter`），撤销权限只需改账号或 ACL，不必同步密钥。
停用绑定账号会连带让该密钥失效（解析时过滤 `enabled`）。

### 10.3 工作区（域）级授权
见 §3.1。

### 10.4 钉钉组织同步

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/dingtalk/sync` | 递归部门 → 拉人 → 按 `(external_source='dingtalk', external_id=userid)` upsert 本地账号；返回 `SyncResult`；未配置返回 400 |

```text
SyncResult { departments, users, created, updated, skipped, truncated }
```

同步规则：**永不给 admin**（`defaultRole` 填 admin 会降为 ops）；用户名按外部 id 确定性生成为 `dt_<id>`；
与人工建的同名账号冲突则跳过（计入 `skipped`）；部门数/用户数有上限，超限 `truncated=true`。
同步进来的账号**无密码**（`password_hash` 为空），不能走密码登录。

## 11. 对外接入

### 11.1 外部 REST

外部系统用 API Key 调用**现有只读接口**即可（不新增对外 REST 端点）：

```text
curl -X POST http://127.0.0.1:9090/api/retrieval/search \
     -H 'X-API-Key: <密钥>' -H 'Content-Type: application/json' \
     -d '{"domainCode":"policy","question":"出差住宿标准"}'
```

可用 `X-API-Key` 或 `Authorization: Bearer <密钥>`。写操作仍受角色门（`service` 角色非 admin → 403）。
`/api/auth/**` 不接受 API Key。

### 11.2 MCP（`POST /api/mcp`）

Streamable HTTP 上的 JSON-RPC 2.0 服务端（手写实现，未引官方 SDK）。鉴权同上（Bearer = API Key）。

| 项 | 值 |
|---|---|
| 端点 | `POST /api/mcp` |
| 协议版本 | `2025-06-18`（`initialize` 会**回显客户端申报的版本**；未申报则回此值） |
| 会话 | 无状态，不返回 `Mcp-Session-Id` |
| 通知 | `notifications/*`（如 `notifications/initialized`）返回 **202 空体** |
| GET | 405（未认证先 401） |

方法：`initialize` / `ping` / `tools/list` / `tools/call`（`notifications/initialized` 无响应）。

工具（4 个，全部走既有服务、用调用账号的身份，权限与问答完全一致）：

| 工具 | 参数 | 说明 |
|---|---|---|
| `search_documents` | `domainCode`(必填)、`question`(必填)、`topN?`、`minScore?` | 检索并返回带出处的证据片段 |
| `list_domains` | — | 列出当前身份可见的知识域 |
| `read_document` | `documentId`(必填)、`maxChars?` | 按 id 读原文（校验域级/文档级权限与现行状态），默认截断到 8000 字符 |
| `search_images` | `domainCode`(必填)、`query`(必填)、`topN?` | 找图（见 §12）；返回 assetId、来源文档、页码、描述与 `/api/media/{id}/raw` 地址（文本，不给二进制） |

错误语义：参数不合法 / 未知工具 → `-32602`；未知方法 → `-32601`；请求体非单个 JSON 对象（含批量数组）→ `-32600`；
JSON 语法错误 → `-32700`。**工具执行失败**（权限不足 / 向量化不可用）不是协议错误，而是 HTTP 200 +
`{"result":{"content":[{"type":"text","text":"…"}],"isError":true}}`。

> 该端点在 `/api/**` 默认拒绝之内，因此浏览器会话（含 `viewer`）同样可调；如不希望如此，可再叠角色门。

## 12. 找图（图片素材，`/api/media`）

把文档里的内嵌图、以及直接上传的图片，建成可检索的图片素材库。**只有 `现行` 文档的图片能被搜到**；
图片的可见性完全由所属文档的**域级 + 文档级 ACL** 决定（不另立权限路径）。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/media/search` | 登录 | `{domainCode, query, topN?, minScore?}` → `{images: [ImageItem], notice}`；**三路召回**（文本向量 + 关键词 + 可选的视觉向量）RRF 融合，"现行"与 ACL 都在 SQL 里下推 |
| GET | `/api/media/{id}/thumbnail` | 登录 + 文档 ACL | JPEG 缩略图；权限按**资产所属文档**复核，写审计（`channel=IMAGE`），`Cache-Control: no-store` |
| GET | `/api/media/{id}/raw` | 登录 + 文档 ACL | 原图字节，同样复核权限与留痕 |
| POST | `/api/media/reindex?force=` | **admin** | 重建图片索引（不动文本 chunk）→ `AssetReindexSummary` |

```text
ImageItem { assetId, documentId, docNo, title, version, page, caption, score, thumbnailUrl, rawUrl }
AssetReindexSummary { total, indexed, skipped, failed }
```

- 图片不存在与无权访问**同形**（403 固定文案），不暴露存在性。
- 图片字节必须走浏览器 `fetch` + `Authorization`（`<img src>` 不会带令牌）。
- 检索不可用（向量化/存储异常）返回 **503**，不伪装成"没找到"。
- 图片用**文本 embedding** 对 `caption + ocr`（VLM 生成的描述与图内文字）编码；若另行启用
  `image_embedding`，则**再加一路视觉向量**（多模态模型把图片与查询文本编码进同一空间），补上"描述里没提到的纯视觉特征"。
  未启用视觉向量时，纯视觉特征搜不到（V1 边界）。
- 图片资产落盘为内容寻址（`{assetRoot}/{sha[0:2]}/{sha[2:4]}/{sha}.{ext}`），同一张图只存一份、只描述一次。
- MCP 侧对应工具 `search_images`（见 §11.2）；**不**把图片混进问答/深度分析的证据。
