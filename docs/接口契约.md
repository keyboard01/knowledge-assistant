# 接口契约

> 适用版本：2026-10-08（P1 + P2 已收口）
> 契约以代码为准（`backend/src/main/java/com/hykj/assistant/**/*Controller.java`），本文是摘要，
> 字段名与类型都取自代码里的 record 定义。

---

## 1. 通用约定

| 约定 | 内容 |
|---|---|
| 基址 | 后端 `http://127.0.0.1:9090`；前端开发时经 Vite 代理 `/api` → 9090 |
| 鉴权 | 除 `POST /api/auth/login` 外全部需要 `Authorization: Bearer <token>`；令牌是**不透明**值，服务端只存 SHA-256 |
| 身份来源 | **只能**由服务端会话推出（`CurrentUser`）。请求体里没有用户、角色、可见范围字段——传了也不生效 |
| 错误体 | 统一 `{"error": "<中文说明>"}` |
| 状态码 | `400` 参数不合法 · `401` 未登录/凭据错 · `403` 角色不足 · `404` 资源不存在 · `503` 模型或内核不可用 |
| 403 vs 401 | 会话有效但角色不够是 403；会话无效是 401。前端据此决定"踢回登录页"还是"提示无权限" |
| 503 的语义 | **系统坏了**，不是"知识库里没有"。后者永远走 200 + 拒答（`refused=true`） |

## 3. 知识域与自检（`/api/domains`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/domains` | 登录 | `{domains: [DomainView]}`；`visibleDocuments` 是**当前身份可见**的文档数 |
| POST | `/api/domains` | **admin** | `{code, name, description?, workspaceSlug?, enabled?}` → `DomainView`；**只落本地登记，不建内核工作区**；code 限 `[a-z][a-z0-9_-]{1,31}` |
| PUT | `/api/domains/{code}` | **admin** | `{name?, description?, enabled?}` → `DomainView`；改 code / workspace_slug 不支持 |
| DELETE | `/api/domains/{code}` | **admin** | 204；**有文档则 400**（先清理或改为停用）；内核工作区不随之删除 |
| POST | `/api/domains/{code}/provision` | **admin** | 单个域的内核工作区初始化（幂等）→ `{domainCode, workspaceSlug, action, message}` |

| GET | `/api/domains/selfcheck` | 登录 | 内核自检；`{ok, vectorCount, items: [{key, title, status, detail}]}`；启动时也会自动跑一次 |

```text
DomainView { code, name, workspaceSlug, description, enabled, visibleDocuments }
```

字段是白名单钉死的：**没有"文档总数 / 隐藏数"字段**，避免通过接口反推隐藏了多少文档。

## 4. 文档与同步（`/api/documents`、`/api/ingest/**`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/documents` | 登录 | `{documents: [DocumentView]}`，**只返回当前身份可见的** |
| POST | `/api/ingest/scan` | admin | 扫目录并按 manifest 登记表同步；`ScanSummary` |
| POST | `/api/ingest/reindex?force=` | admin | 重建自建 chunk；`force=true` 连内容没变的也重算；`ReindexSummary` |
| GET | `/api/ingest/tasks?limit=` | admin | `{tasks: [...]}`，limit 被夹到 1..500 |
| POST | `/api/ingest/tasks/{id}/retry` | admin | `FileResult` |
| POST | `/api/ingest/retry-failed` | admin | `{ok, results: [FileResult]}` |
| POST | `/api/ingest/parse-preview` | admin | `{documentId}` → `ParsePreview`：块级解析预览，与入库**同一条解析路径**（版面分析可用则用，否则内置），供人工确认解析质量 |
| POST | `/api/ingest/upload` | admin | `multipart/form-data`：`file`(pdf/docx) + `domainCode/docNo/title/version` + 可选 `docStatus/secrecy/ownerDept/effectiveFrom/effectiveTo` → `FileResult`。写盘 + 登记 `manifest.json` + 入内核 + 解析 + 按密级写 ACL；同一「编号+版本」重复上传视为覆盖。单文件上限 50MB |
| PUT | `/api/documents/{id}/status` | admin | `{docStatus}`（现行 / 已废止 / 草案·未生效）→ `DocumentView`；只改状态，不重传、不重解析 |
| GET | `/api/documents/{id}/content` | 登录 + 文档 ACL | Markdown 视图（JSON，`ContentView`） |
| GET | `/api/documents/{id}/file` | 登录 + 文档 ACL | 原文预览：**内联** PDF（DOCX 服务端重排成 PDF），字节带水印 |
| GET | `/api/documents/{id}/download` | 登录 + 文档 ACL | 下载：**统一给 PDF**（同一份带水印字节），`Content-Disposition: attachment` |

```text
DocumentView { id, domainCode, docNo, title, version, docStatus, secrecy, ownerDept,
               mimeType, fileSize, indexStatus, chunkStatus, chunkCount, kernelDocName, lastError }
ContentView  { documentId, domainCode, docNo, title, version, docStatus, secrecy, ownerDept,
               mimeType, originalPdf, watermarkText, markdown, blocks: [Block],
               pageOfChunk: {chunkId → 起始页}, chunkCount }
Block        { chunkId, kind, level, text, pageFrom, pageTo, sectionPath, sectionHead }
ScanSummary  { sourceRoot, startedAt, scanned, uploaded, skipped, failed,
               vectorCountBefore, vectorCountAfter, files: [FileResult] }
FileResult   { sourcePath, action, status, detail, domainCode, documentId }
ReindexSummary { total, indexed, skipped, failed, results: [...] }
```

`DocumentView` 刻意**不含** `sourcePath`（服务器内网路径）、`contentHash`、内核内部 id——这些是内部信息，
viewer 没必要看到。`vectorCountBefore/After` 是"上传成功 ≠ 入库成功"那条判据的对外证据。

### 4.1 查看三入口的共同口径（§13）

| 口径 | 说明 |
|---|---|
| 权限 | 每次请求**重新判**文档级 ACL（与列表、检索共用 `AccessFilter`）。**不存在与无权限同码**：一律 `403 {"error":"没有权限查看该文档"}`，响应体不含标题、编号、路径——否则仅凭状态码就能枚举库里有编号哪些文档 |
| 未登录 | `401`（走统一的登录拦截） |
| 水印 | PDF 由服务端**烧进字节**（45° 半透明重复，`账号 yyyy-MM-dd`，日期取服务端当天）。Markdown 视图无字节可烧，只在页面叠加 |
| 体积 | 源文件 > 20MB → `413 {"error":"文档体积 NNMB 超过在线查看上限 20MB，…"}`。水印要整份重写字节，没有 HTTP Range 分页这条路 |
| 审计 | 每次请求落一行 `document_view_log`（channel = `FILE`/`CONTENT`/`DOWNLOAD`，outcome = `OK`/`DENIED`，含水印串与来源 IP）。**拒绝也记**：那是最该被看见的事件。写审计失败只记 error 日志，不影响本次查看 |
| 只读 | 查看不改任何库内值：`content_hash`、`index_status`、`chunk_count`、`document_chunk` 行数在查看前后不变 |
| 缓存 | `Cache-Control: no-store`；DOCX 重排结果只缓存**未盖章**的字节（带某账号水印的成品绝不跨人缓存） |

## 5. 检索（`/api/retrieval/search`）

| 方法 | 路径 | 权限 | 请求 |
|---|---|---|---|
| POST | `/api/retrieval/search` | 登录 | `{domainCode, question, topN?, minScore?}` |

```text
RetrievalResult { evidences: [Evidence], insufficient, hint, accessNotice, diagnostics }
Evidence   { rank, documentId, docNo, title, version, docStatus, secrecy, ownerDept,
             kernelDocName, bestScore, fragments: [Fragment] }
Fragment   { chunkId, chunkIndex, text, score, distance, wordCount, pageFrom, pageTo, sectionPath,
             kind, keywordScore, vectorRank, keywordRank }
RetrievalDiagnostics { accessFilter, requestedTopN, minScore, answerMinScore, keywordMinScore,
                       kernelTopN, kernelHits, vectorHits, keywordHits, bestKeywordScore,
                       droppedUnauthorized, droppedUnknown, droppedNotIndexed, droppedDuplicate,
                       elapsedMs, rerankApplied, bestRerankScore, ... }
```

**重排（P0）**：`rerankApplied` 表示本次是否真的走了 cross-encoder 重排（未配置/失败时 `false`），
`bestRerankScore` 是本次最强重排分。重排**只改排序、不改口径**：`bestScore` 仍是**全局最强的向量余弦**
（不随重排换第一名而变），作答阈值 `answerMinScore` / `keywordMinScore` 也一字不动。重排失败一律 fail-open
（退回 RRF 原序），不影响检索是否出结果。

两个提示字段的读者不同，**不要合并**：

- `hint` 面向排障：为什么答不上来，含"没凑满 topN"这类接口层面的信息；
- `accessNotice` 面向用户：你看到的答案缺了证据（"另有 N 条更相关的命中你无权访问"）。

`diagnostics.droppedUnknown / droppedNotIndexed` 非 0 说明**内核有本地登记表里没有的命中**或**文档还没索引**，
这是运维信号，不是用户信号。

## 6. 问答（`/api/generation`）

| 方法 | 路径 | 权限 | 请求 |
|---|---|---|---|
| POST | `/api/generation/answer` | 登录 | `{domainCode, question, topN?}` |
| POST | `/api/generation/answer/stream` | 登录 | 同上；响应是 `text/event-stream` |

```text
GeneratedAnswer { answer, citations: [Citation], refused, refusalReason, notice,
                  evidences: [Evidence], diagnostics }
Citation { rank, documentId, docNo, title, version, chunkId, pageFrom, pageTo }
```

**SSE 事件序列**（`evidences` → `delta`* → `verdict`，出错则 `error`）：

| 事件 | 载荷 | 说明 |
|---|---|---|
| `evidences` | `{evidences: [Evidence], insufficient}` | 先给证据，让界面能立即展示"检索到了什么" |
| `delta` | `{text}` | 正文增量；此时**结论未定** |
| `verdict` | `GeneratedAnswer` | 校验后的最终结论（引用越界/截断在这里才定为拒答） |
| `error` | `{error}` | 一旦推过第一个事件，HTTP 状态码已经是 200，失败**只能**靠这个事件表达 |

`refused=true` 时 `refusalReason` 是原因码（可统计），`evidences` 照样返回——用户需要知道检索到了什么，
才能判断是问题问偏了，还是库里确实没有。

## 7. 运行记录（`/api/observe/**`，整个控制器 `@RequireRole("admin")`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/observe/traces?limit=&domainCode=&refused=` | `{traces: [TraceRow], summary}`；`refused` 三态：不传=全部 / true=只看拒答 / false=只看放行 |
| GET | `/api/observe/traces/{id}` | `TraceDetail`；不存在 404 |
| GET | `/api/observe/summary?domainCode=&refused=` | `Summary` |
| GET | `/api/observe/price` | `PriceSnapshot`，供界面说明"费用按什么价算" |

```text
TraceRow   { id, createdAt, userName, domainCode, question, refused, refusalRule, insufficient,
             evidenceCount, citedCount, bestScore, modelCalled, promptTokens, completionTokens,
             totalElapsedMs, costTotal, priced }
TraceDetail(TraceRow, accessFilter, requestedTopN, minScore, answerMinScore, kernelTopN, kernelHits,
            droppedUnauthorized, droppedUnknown, droppedNotIndexed, droppedDuplicate, documentCount,
            versionConflict, retrievalElapsedMs, generationElapsedMs, model, outOfRangeCitations,
            truncated, promptPricePer1k, completionPricePer1k, evidences: [EvidenceRow])
EvidenceRow { rank, documentId, docNo, title, version, chunkId, chunkIndex, score, cited,
             pageFrom, pageTo, vectorRank, keywordRank, keywordScore }
Summary    { total, refused, insufficient, refuseRate, modelCalls, promptTokens, completionTokens,
             costTotal, pricedCount, unpricedCount, avgElapsedMs, maxElapsedMs, avgBestScore }
PriceSnapshot { promptPer1k, completionPer1k, note }
```

`cited` 是"模型有没有引用它"，不是"有没有权限"——权限在检索阶段就判完了。
`costTotal` 为 `null` 表示**未计费**（没配单价），不是 0 元。
`chunkIndex` 是片段在文档内的序号（`document_chunk` 的唯一约束 `(document_id, chunk_index)` 的另一半）。
`chunkId` 是代理键（bigserial），强制重解析在历史上会换掉它；`(documentId, chunkIndex)` 不会漂移，
"点回原文"要用这一对。`null` 表示没有本地序号（内核通道来的片段，或历史悬空行）。

## 8. 配置（`/api/settings`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/settings` | 登录 | `{groups: [GroupView]}` |
| PUT | `/api/settings/{code}` | 登录 | `{values: {字段: 值}}` → `GroupView`；**只有这里允许携带明文密钥** |
| POST | `/api/settings/{code}/test` | 登录 | `TestResult {ok, message, detail}`，真实探活 |
| DELETE | `/api/settings/{code}/{field}` | 登录 | 清空单个字段 → `GroupView` |

`code` ∈ `anythingllm` / `embedding` / `llm` / `ingest` / `rerank`（P0 重排）/ `layout`（P1 版面分析）。
`ingest` 分组含 `contextual`（P1 片段上下文增强，默认 false）；`rerank` / `layout` 均为可选能力，默认关闭。

```text
GroupView { code, title, description, fields: [FieldView] }
FieldView { key, label, secret, hasValue, mask, value, hint, defaultValue }
```

**密钥字段三条硬规则**（AC-P1-012 / AC-P1-013）：

1. `secret=true` 的字段，`GET /api/settings` 里 `value` **恒为空串**，只回 `hasValue` 与掩码（形如 `sk-****1234`）；
2. 掩码与明文不可互推；
3. 保存配置的 PUT 体里可以带明文，但**不写日志**、响应体也不回显明文。

`llm.apiKey` 留空时回落到 `embedding.apiKey`（同一套账号时的便利，界面会显示"复用向量化分组的 Key"）。
注意：本项目当前 `llm.baseUrl` 与 `embedding.baseUrl` **不是同一个服务商**，所以这条回落只是在"两边同源"时才有意义。

## 9. 深度分析（`/api/deep`，P3a）

| 方法 | 路径 | 权限 | 请求 |
|---|---|---|---|
| POST | `/api/deep/answer` | 登录 | `{domainCode, question, runId?, maxSubQuestions?, maxToolCalls?, maxRounds?, maxElapsedMs?, maxCompletionTokens?}` |
| POST | `/api/deep/answer/stream` | 登录 | 同上；响应是 `text/event-stream` |
| POST | `/api/deep/cancel` | 登录 | `{runId}` |

```text
DeepAnswer { runId, domainCode, question, mode="deep", answer,
             sections: [Section], plan: [SubQuestion], steps: [Step], citations: [Citation],
             refused, refusalRule, notice, clarifyQuestion, stopReason, stopMessage,
             evidences: [Evidence], diagnostics: DeepDiagnostics }
Section     { index, question, text, citedRanks: [int], answered, refusalRule }
SubQuestion { id, question, why }
Step        { seq, action, detail, query, documentId, fromChunkIndex, newFragments, elapsedMs }
DeepDiagnostics { model, modelCalled, subQuestionCount, sectionCount, answeredSections, evidenceCount,
                  citedCount, toolCalls, rounds, promptTokens, completionTokens, elapsedMs,
                  budgetStop, stopReason }
```

**预算字段只能往小里填**：子问题 ≤4、工具调用 ≤10、轮数 ≤3、耗时 ≤120000ms、输出 token ≤12000；
超上限按上限算，不报错（`DeepBudget.of` 一侧夹死，前端拦不拦都不影响）。

**SSE 事件序列**（`plan` → `step`* → `evidences` → `delta`*/`section`* → `verdict`，出错则 `error`）：

| 事件 | 载荷 | 说明 |
|---|---|---|
| `plan` | `{runId, plan: [SubQuestion], budget}` | 拆成了哪几条子问题；此时还没开始检索 |
| `step` | `{step}` | 每一步查了什么、新带回几段——前端画"探索过程"靠它 |
| `evidences` | `{evidences: [Evidence], insufficient}` | 合并去重后的证据（全局连续编号） |
| `delta` | `{text}` | 分段正文的增量；与快速问答一样，此时结论未定 |
| `section` | `{section}` | 某一段子问题答完了（带 `citedRanks`），界面可以定稿这一段 |
| `verdict` | `DeepAnswer` | 最终结论 |
| `error` | `{error}` | 推过第一个事件后 HTTP 已是 200，失败只能靠这个事件表达 |

**`stopReason` 是合法状态而不是错误**，取值与含义：

| 取值 | 含义 |
|---|---|
| `DONE` / `MODEL_FINISH` | 证据齐了 / 模型说够了 |
| `NO_NEW_EVIDENCE` | 这一轮没有带回新片段——证据已到边界（不是"没查到"） |
| `REPEATED_QUERY` / `REPEATED_READ` | 模型重复了已经试过的查询 / 已经读过的那一段 |
| `PLANNER_UNUSABLE` | 模型没给出可识别的下一步动作，按现有证据作答 |
| `TOOL_CALL_BUDGET` / `ROUND_BUDGET` / `ELAPSED_BUDGET` / `TOKEN_BUDGET` | 触到预算上限（`diagnostics.budgetStop` 里是给人看的说明） |
| `CANCELLED` | 用户调了 `/api/deep/cancel`：返回"已取消"与已完成的部分，HTTP 仍是 200 |
| `CLARIFY` | 一条证据都没有，而拆解判定问题缺关键限定：`clarifyQuestion` 是要反问用户的那句话 |

`refused=true` 表示**知识库里没有**（`refusalRule` 给原因码）；模型/内核不可用仍然是 `503`，与拒答分开。
澄清是"先查后问"：只有查过一轮仍没有任何证据、且拆解阶段判了 `needClarification`，才会走到 `CLARIFY`。

`POST /api/deep/cancel` 返回 `{cancelled: bool, note}`。取消别人的 `runId` 与"这个 `runId` 不存在"
返回同一句话（"该运行已结束或不存在"）——否则它就成了一个探测"别人在问什么"的工具。
