# 交付部署文档

> 从零把系统跑起来。全部组件监听 `127.0.0.1`，适合单机部署 / 内网交付。
> 功能见 [`功能说明.md`](功能说明.md)，架构见 [`架构说明.md`](架构说明.md)。

---

## 1. 组件与端口

| 组件 | 形态 | 地址 | 说明 |
|---|---|---|---|
| PostgreSQL 17 + pgvector | Docker 容器 `assistant-pg` | `127.0.0.1:5432` | 库/用户均为 `assistant`，数据卷 `assistant_pg_data` |
| 知识内核 AnythingLLM | Docker 容器 `assistant-anythingllm` | `127.0.0.1:3002` | 独立实例；密钥从数据库读 |
| 后端 | 本机 JVM（可执行 jar） | `127.0.0.1:9090` | Spring Boot 3.5（Java 17） |
| 前端 | Vite | `127.0.0.1:5173` | `/api` 由 Vite 代理到后端 |

> 后端用 **9090**（不用 8080，是为了避开同机其它项目）。要改端口需同步改三处：
> `backend/src/main/resources/application.yml` 的 `server.port`、`frontend/vite.config.js` 的代理目标、`tools/*.ps1` 里的地址。

## 2. 前置环境

| 依赖 | 版本 | 校验命令 |
|---|---|---|
| Docker Desktop | 任意较新版 | `docker --version` |
| JDK | **17** | `java -version`（必须显示 17） |
| Maven | 3.9+ | `mvn -v` |
| Node.js | 18+ | `node -v` / `npm -v` |

> ⚠️ 后端必须用 **JDK 17**。若本机 `java -version` 是 8，会报 `UnsupportedClassVersionError` 或编译期"非法字符"（Java 8 不支持文本块）。
> 解决：把 `JAVA_HOME` 指到 JDK17，或在启动脚本前设置：
> ```powershell
> $env:JAVA_HOME = "<你的 JDK17 路径>"
> $env:Path = "$env:JAVA_HOME\bin;$env:Path"
> ```

## 3. 拉取镜像

```powershell
# 数据库（带 pgvector 扩展）
docker pull pgvector/pgvector:pg17

# 知识内核 AnythingLLM
docker pull mintplexlabs/anythingllm:latest
```

离线环境：在有网机器上 `docker save` 出 tar，拷贝后 `docker load`。

## 4. 准备配置

```powershell
cd <项目根目录>
copy deploy\.env.example deploy\.env
```

编辑 `deploy\.env`：

```ini
PG_HOST=127.0.0.1
PG_PORT=5432
PG_DB=assistant
PG_USER=assistant
PG_PASSWORD=<给数据库设一个密码>

ANYTHINGLLM_BASE_URL=http://127.0.0.1:3002
ANYTHINGLLM_API_KEY=<AnythingLLM 开发者 Key；暂时没有可留空，之后再填并重建内核>

ASSISTANT_ADMIN_PASSWORD=<管理员初始密码，至少 8 位>
ASSISTANT_DEMO_PASSWORD=<演示账号密码，可留空>
```

> `deploy\.env` 绝不会进 Git（已在 `.gitignore`）。
> 账号口令**只在账号不存在时用于初始化**，之后改 `.env` 不会覆盖已有账号。

## 5. 启动数据库

```powershell
docker run -d --name assistant-pg --restart unless-stopped `
  -p 127.0.0.1:5432:5432 `
  -e POSTGRES_USER=assistant `
  -e POSTGRES_PASSWORD=<deploy\.env 里的 PG_PASSWORD> `
  -e POSTGRES_DB=assistant `
  -v assistant_pg_data:/var/lib/postgresql/data `
  pgvector/pgvector:pg17
```

**不需要手工建表**：后端启动时会幂等执行 `backend/src/main/resources/db/schema.sql`（建表 + 索引 + 种子数据）。

验证：

```powershell
docker ps --format "{{.Names}}  {{.Status}}"
```

## 6. 构建并启动后端

```powershell
$env:JAVA_HOME = "<你的 JDK17 路径>"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"

cd backend
mvn -o -B package            # 离线可构建；产出 target\knowledge-assistant-0.1.0-SNAPSHOT.jar
cd ..

pwsh deploy\restart-backend.ps1   # 停旧进程 → 启动 → 等就绪 → 打印内核自检
```

- 日志：`backend\logs\app.log` / `app.err.log`；PID：`backend\logs\app.pid`。
- 必须在**不受沙箱/防火墙限制的终端**里启动，否则 JVM 出网被拦，模型调用全失败。

---

## 7. 启动知识内核（可选，但建议）

内核从**数据库**读模型配置，所以顺序是：**后端先起来 → 在「系统配置」填好向量化/生成模型 → 再启动内核**。

```powershell
pwsh deploy\start-kernel.ps1
```

（脚本会从 `app_setting` 读取配置并重建容器；配置缺失时会明确报错。）

## 8. 启动前端

```powershell
cd frontend
npm install        # 首次
npm run dev        # http://127.0.0.1:5173
```

生产构建：`npm run build`（产物落 `frontend\dist`）。

## 9. 一键启动（推荐日常使用）

Windows 下双击根目录 **`启动.bat`**，它会自动：

1. 切到 JDK 17 → 2. 起数据库容器 → 3. 起内核容器（仅当未运行）→ 4. 缺 jar 时打包 → 5. 起后端并等就绪 → 6. 起前端并开浏览器。

停止：双击 **`停止.bat`**（停后端与前端；**容器保留**，要停容器用 `docker stop assistant-anythingllm assistant-pg`）。

参数：`启动.bat -Rebuild`（强制重打包）、`-SkipFrontend`、`-NoBrowser`。

---

## 10. 首次使用

浏览器开 `http://127.0.0.1:5173`，用 `admin` + `deploy\.env` 里的初始口令登录：

1. **系统配置**：填「向量化 Embedding」与「生成模型出口」两组的接口地址、模型名、API Key（兼容 OpenAI 协议），点「测试连接」确认可用。
2. **知识域与内核**：新建知识域 → 「初始化工作区」。
3. **文档与同步**：上传文档，或放目录后「立即同步」。
4. **知识问答**：选域提问，看带引用的答案。

## 11. 停服与重置

```powershell
# 停后端
Stop-Process -Id (Get-Content backend\logs\app.pid)

# 清空内核重来（索引会丢，之后需重新同步）
docker rm -f assistant-anythingllm
pwsh deploy\start-kernel.ps1
```

数据库重置是破坏性操作（`docker rm -f assistant-pg` 只删容器，数据在命名卷 `assistant_pg_data` 里；要连数据一起删需删卷）——执行前请确认目标卷。

## 12. 数据与备份

| 数据 | 位置 |
|---|---|
| 元数据 / 权限 / 片段与向量 / 运行账本 / 配置与密钥 / 会话 | PostgreSQL（Docker 卷 `assistant_pg_data`） |
| 原始文档 + `manifest.json` | 项目内 `knowledge/` |
| 内核工作区、上传副本、内核向量库 | 内核容器挂载目录（`deploy\start-kernel.ps1` 里 `-StorageDir`，默认 `D:\DockerData\AnythingLLM-assistant`） |
| 后端日志 | `backend\logs\` |

**备份需同时带走**：PG 卷 + `knowledge/` + 内核挂载目录 + `deploy\.env`。

## 13. 常见故障

| 现象 | 原因 / 处理 |
|---|---|
| `Port 9090 was already in use` | 端口被占：换端口（同步改 yml / vite.config.js / tools 脚本）或停占用进程 |
| `UnsupportedClassVersionError` / 编译"非法字符" | 用了 Java 8：`JAVA_HOME` 切到 JDK 17 |
| 问答 503 | 生成模型出口不可用（Key/地址/出网），不是"库里没有" |
| 检索 503 | 内核容器未起；或 `assistant.retrieval.mode` 配置问题 |
| 上传 200 却检索不到 | 内核会吞掉嵌入失败仍返回 200：看日志与内核向量数增量判成败 |
| 工作区名变成 uuid | 内核对中文名 slugify 会变空串：用英文 slug 建，再改中文显示名 |
| 找不到 `deploy\restart-backend.ps1` 报 Java 版本错 | 该脚本用 PATH 里的 `java`：先设 `JAVA_HOME`，或用 `启动.bat` |
