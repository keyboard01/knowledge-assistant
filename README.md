# 企业知识助手（Knowledge Assistant）

一个本地部署的企业知识库问答系统：把公司制度 / 技术文档 / 维修手册等资料入库，用**混合检索（向量 + 关键词）+ 重排**找出证据，再让大模型**只依据证据作答并标注引用**；证据不足时明确拒答，不瞎编。

- 后端：Spring Boot 3.5（Java 17）
- 前端：Vue 3 + Vite
- 存储：PostgreSQL 17 + pgvector（元数据 / 权限 / 片段与向量 / 运行账本）
- 部署形态：单机部署，全部监听 `127.0.0.1`；支持**多租户**（租户 → 知识域两级隔离）

---

## 一、它能做什么

| 能力 | 说明 |
|---|---|
| 混合检索 | 向量召回（pgvector HNSW）+ 关键词召回（pg_trgm），RRF 融合 |
| 权限下推 | **三级**：租户 → 工作区（域）→ 文档级 ACL，都在 SQL 层过滤（fail-closed），不可见内容根本不进候选 |
| 状态闸门 | 只有"现行"文档参与检索与查看；草案 / 已废止既不进证据、也打不开原文 |
| 引用校验 | 每条结论带引用编号，越界/截断按拒答处理，不返回半句话 |
| 拒答闸门 | 双阈值判定"证据是否足够"，不足时不调用模型 |
| 深度分析 | 问题拆解 → 多轮检索 → 分步作答（可选） |
| 重排（P0） | 可选 cross-encoder 重排层，默认关闭 |
| 查询改写 / 上下文增强 / 版面分析（P1） | 均为可选、默认关闭 |
| 管理端 / 用户端分离 | 两个独立入口：用户门户 `/`、管理控制台 `/admin.html` |
| 用户与权限 | 建号 / 改角色 / 停用 / 重置密码；域级授权（谁能看哪个知识域）；禁止停用最后一个管理员 |
| 多租户（多项目接入） | 每个项目一个**租户**；库按租户隔离、`ALL:*` 只对本租户公开；**租户管理员**能管自己租户的域/授权/审核、管不了别的租户；平台管理员跨租户 |
| 文档接入 | 支持 PDF / DOCX / PPTX / XLSX / 图片；管理员上传 / 目录同步；普通用户可在门户提交，落"草案"待审核 |
| 找图（多模态检索） | 把文档内嵌图与直接上传的图片建成素材库；用一句描述检索（视觉模型生成描述与图内文字按文本召回；可选多模态向量做跨模态召回） |
| 对外接入 | API Key（绑定账号、复用权限）+ MCP server（`POST /api/mcp`，3 个工具） |
| 钉钉接入（可选） | 组织通讯录同步 + 钉钉内免登；配置留空即禁用 |
| 运行账本 | 每次问答一行：命中片段、耗时、token、费用 |

## 二、技术亮点

> 设计主线：**凡是能用机制保证的，就不交给模型碰运气**。模型只负责"读证据、写人话"。

**检索**

- **混合召回 + RRF 融合**：向量召回（语义）+ 关键词召回（pg_trgm 精确词）两路并行，用 RRF **只看名次、不把两路分数相加**——余弦相似度与字符 trigram 覆盖率不是同一量纲，相加等于把"米"和"公斤"相加。
- **精确词半票**：查询里的型号 / 编号 / "每 2000 h" 这类词命中时额外加成，够把强命中抬上来，又不至于让关键词压过语义。
- **双阈值闸门**：召回阈值（松）与作答阈值（严）分开；两条路**任一够强**即可作答，都不够强就拒答、**不调用模型**（省 token，且拒答原因可统计）。
- **重排只改名次、不改分数口径**：可选 cross-encoder 精排，失败即 fail-open 退回原序；重排分不进入"相似度"语义，避免污染下游定位。

**安全与可信**

- **权限在检索时就下推**：文档级 ACL 写进检索 SQL（fail-closed），无权限的片段根本不进候选，也不会出现在引用与日志里。
- **"没找到"与"没权限"分开说**：被权限挡下会明确提示"另有 N 条更相关的命中你无权访问"，且不暴露不可见文档是否存在。
- **引用校验**：回答里的引用编号越界、或被 `max_tokens` 截断，一律按拒答处理、不给半句话——专防模型编造来源。
- **版本冲突并列提示**：同一文档编号出现多个版本时并列展示，不悄悄挑一个。

**深度分析**

- **机制上的问题用机制修，不赌模型**：问题拆解后，先确定性地把每份命中文档"锚点前后各 4 段"补齐，再交给模型自选动作——因为"承载答案的表行排在第 7 名之后"是机制问题，不能赌模型会想起来去读它。
- **预算账本**：轮数 / 工具调用 / token / 耗时全程记账，超预算即停；"用户取消"与"预算耗尽"是两种不同的停止出口。

**工程**

- **幂等**：内容哈希判定，没变就不重复上传、不重算向量；写库按 `(document_id, chunk_index)` upsert，**片段 id 稳定**，历史引用不悬空。
- **可选能力默认全关、失败 fail-open**：重排 / 查询改写 / 上下文增强 / 版面分析，关闭时行为与引入前**逐位一致**。
- **运行账本**：每次问答一行——命中片段、两路名次、耗时、token、费用（按提问当时单价快照，事后改价不影响历史账）。

## 三、架构与端口

```
浏览器 (Vite 5173，两个入口)
   │  /api/**（Bearer 会话令牌；外部系统用 API Key，Vite 代理到后端）
   ▼
后端 (Spring Boot 127.0.0.1:9090)
   ├─ security/   登录、会话、API Key、角色、域级+文档级 ACL、租户规则、钉钉 SSO/组织同步
   ├─ tenant/     租户与租户成员（多租户：归属查询 / 角色 / 指派）
   ├─ domain/     知识域：CRUD、域级授权、管理权判定（canAdminister）
   ├─ ingest/     目录扫描 / 上传（用户上传默认草案）、幂等同步、片段入库
   ├─ parse/      PDF(PDFBox) / DOCX(POI) → 块 → chunk
   ├─ retrieval/  召回、RRF 融合、重排、证据组装、双阈值
   ├─ generation/ 提示词、引用校验、拒答
   ├─ mcp/        MCP Streamable HTTP（/api/mcp，复用上面的服务）
   ├─ media/      找图：图片抽取 + 视觉描述 + 图片检索
   └─ observe/    运行账本
   ▼
PostgreSQL 17 + pgvector (127.0.0.1:5432)
钉钉开放平台 oapi.dingtalk.com（可选，出网）
```

| 组件 | 形态 | 地址 |
|---|---|---|
| PostgreSQL + pgvector | Docker 容器 `assistant-pg` | `127.0.0.1:5432` |
| 后端 | 本机 JVM（可执行 jar） | `127.0.0.1:9090` |
| 前端 | Vite（用户门户 `/` · 管理控制台 `/admin.html`） | `127.0.0.1:5173` |

> 端口 9090 而非 8080，是为了避开本机其它项目。

## 六、快速开始

### 1. 准备配置

```powershell
cd <项目根目录>
copy deploy\.env.example deploy\.env
```

编辑 `deploy\.env`，至少填写：

```
PG_PASSWORD=<给数据库设一个密码>
ASSISTANT_ADMIN_PASSWORD=<管理员初始密码，至少 8 位>
ASSISTANT_DEMO_PASSWORD=<演示账号密码，可留空>
```


### 2. 一键启动（推荐）

双击项目根目录的 **`启动.bat`**。它会自动：

1. 切换到 JDK 17（找不到会明确报错）
2. 起数据库容器 `assistant-pg`（不存在则创建）
3. 缺 jar（或产物不可执行）时执行 `mvn -o -B package`
4. 起后端并等到就绪
5. 新窗口起前端，并打开浏览器

停止：双击 **`停止.bat`**（停后端与前端，容器保留）。

可选参数：`启动.bat -Rebuild`（强制重打包）、`-SkipFrontend`、`-NoBrowser`。

### 3. 分步启动（排障用）

```powershell
# (a) 确认容器在跑
docker ps --format "{{.Names}}  {{.Status}}"

# (b) 构建并启动后端（必须先切 JDK 17）
$env:JAVA_HOME = "<你的 JDK17 路径>"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
cd backend
mvn -o -B package
cd ..
pwsh deploy\restart-backend.ps1      # 停旧 → 启动 → 等就绪 → 打印自检

# (c) 启动前端
cd frontend
npm install        # 首次
npm run dev        # http://127.0.0.1:5173
```

## 七、首次使用

浏览器打开 `http://127.0.0.1:5173`（**用户门户**）或 `http://127.0.0.1:5173/admin.html`（**管理控制台**），
用 `deploy\.env` 里的 `admin` 账号登录。管理相关操作都在控制台里。

1. **配置模型**：进入「系统配置」，填「向量化 Embedding」与「生成模型出口」两组的**接口地址、模型名、API Key**（都是兼容 OpenAI 协议的地址），点「测试连接」确认可用。
2. **建知识域**：「知识域管理」→「新建知识域」（代码用英文小写）。
3. **入库文档**（二选一）：
   - 「文档与同步」→「上传文档」，填编号/标题/版本等并选文件；
   - 或把文件放进 `knowledge/<域>/` 并在 `knowledge/manifest.json` 登记，再点「立即同步」。
4. **提问**：「知识问答」选知识域 → 输入问题 → 得到带引用编号的答案；点「看原文」可跳转原文并高亮被引用的片段。
5. **看账本**：管理员可在「运行记录」查每次问答的命中、耗时、token 与费用。

## 十、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 后端启动报 `Port 9090 was already in use` | 端口被占；改 `backend/src/main/resources/application.yml` 的 `server.port`，并同步改 `frontend/vite.config.js` 与 `tools/*.ps1` 里的地址 |
| 启动报 `UnsupportedClassVersionError` | 用了 Java 8；把 `JAVA_HOME` 切到 JDK 17 |
| 编译报一堆"非法字符" | 同上，用的是 Java 8，不支持文本块 |
| 问答报 503 | 生成模型出口不可用（Key/地址/出网被拦），不是"库里没有" |
| 检索报 503 | 向量化服务不可用（embedding 地址/Key/出网被拦） |

## 十二、已知限制与暂不支持

> 本系统目前聚焦**文本文档**的检索与问答。以下能力**尚未支持**，是已知边界，不是隐藏缺陷：

| 类别 | 现状 | 影响 |
|---|---|---|
| **图片 / 图表** | 已支持**找图**：从 PDF / DOCX / PPTX 抽取内嵌图、也可直接上传图片，用视觉模型生成描述与图内文字后按文本检索。但仍**不做图文问答**，也不把图片混进问答证据 | 默认不建跨模态向量（需另开「图片视觉向量」），纯视觉特征可能搜不到；问答依旧只依据文字证据 |
| **扫描件（无文字层的 PDF）** | **无 OCR**。只有图片、没有文字层的 PDF 解析结果为空 | 整份文件无法检索；入库时会因"解析结果为空"被拒绝并报错 |
| **复杂 PDF 表格** | 内置 PDFBox 解析为启发式，恢复不出"表头—单元格"关系，单元格直接拼接；跨页表格可能丢行 | 表格类问题召回偏弱；需依赖可选的版面分析服务（Docling / MinerU / PP-StructureV3）改善 |
| **复杂排版** | 双栏、跨页表格等内置解析为启发式，识别率无保证 | 同上，需外部版面分析服务 |
| **多模态 / 音视频** | 未实现 | —— |

其它已知边界：

- 单机部署，全部监听 `127.0.0.1`；不做分布式向量库。多租户已支持（租户 → 知识域两级隔离、租户管理员，见 [`docs/多项目接入方案.md`](docs/多项目接入方案.md)）；**仍未做**：租户的建/停/删 API 与租户管理员自助管成员（S4）。
- 存储为 PostgreSQL + pgvector 单库；向量维度写死在 DDL，**换向量化模型需全量迁移**。
- 文档**没有删除接口**，下线只能改状态（现行 / 已废止 / 草案）。
- 工作区授权只有"读"：可见即可上传，用户上传靠"默认草案 + 审核 + 覆盖守卫"兜底。
- 对外 API Key 没有 scopes，权限完全等于绑定账号的角色/部门——**绑 `admin` 的 Key 就是管理员权限**（能上传、改状态、改配置）；Key 也没有有效期与 IP 白名单。要"只读的钥匙"目前只能造一个受限账号再绑。详见 [`docs/多项目接入方案.md`](docs/多项目接入方案.md)。
- MCP 只提供 Streamable HTTP（`POST /api/mcp`），没有 stdio 传输：影响只在客户端——Claude Desktop 这类默认只启动本地进程的客户端需要自备 stdio↔HTTP 桥，能配远程 MCP 的客户端不受影响。服务端是多用户 + ACL 的系统，stdio 的"进程即身份"与它不匹配。
- 钉钉**未做真实联调**（本机无凭据、需出网），只验证到"留空即禁用 + 纯逻辑单测"；钉钉出站（发消息）尚未实现。
- **找图需要配「图片理解」视觉模型**（系统配置 → 图片理解，默认关闭）；未配置时图片不抽取、不描述，文档仍正常入库。
  仅开「图片理解」时靠文字描述检索；要命中纯视觉特征需再开「图片视觉向量」（多模态模型，如 `qwen2.5-vl-embedding`）。
- ~~**文档查看器不渲染内嵌图片**~~ **（2026-10-14 已修）**：PPTX 的内嵌图按幻灯片插回「原文」页签（图片不进 chunk 正文，切分与检索零接触）；Markdown 页签按约定仍只出文字。DOCX 的图没有页码语义，排在文末。
- **文本文档支持 PDF / DOCX / PPTX / XLSX**；旧 `.ppt` / `.xls` 不支持（前者离线无 `poi-scratchpad`）；PPT 生成未实现；扫描件（无文字层 PDF）仍无 OCR。XLSX 只取单元格文本（工作表名成标题、行带表头前缀），表内图片与图表不抽取。
- 面向中文语料优化，其它语种效果未验证。

## 十四、安全提示

- 所有密钥只存在服务端（`deploy/.env` 或数据库 `app_setting`），接口只回显掩码。
